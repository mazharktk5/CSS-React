1. THE FIRST QUESTION
================================================================================

When you write HTML like this:

    <h1>Hello</h1>
    <p>Welcome</p>
    <button>Click Me</button>

Can JavaScript directly understand this HTML?

❌  NO.

JavaScript cannot work directly with HTML files.
JavaScript doesn't read HTML tags. It doesn't understand angle brackets.
So how does a webpage ever become interactive?

The browser solves this. Let's follow the full journey step by step.

================================================================================
2. WHAT THE BROWSER DOES WITH YOUR HTML
================================================================================

STEP 1 — You Write HTML (just text in a file)
──────────────────────────────────────────────

    <!DOCTYPE html>
    <html>
      <body>
        <h1>Hello</h1>
        <button>Click Me</button>
      </body>
    </html>

This is just a TEXT FILE saved on your computer.
At this point, it's no different from a .txt file. Just words and symbols.

STEP 2 — Browser Opens the File
─────────────────────────────────

When Chrome (or any browser) opens your HTML file, it reads the text.
But it does NOT keep it as plain text.

Instead, the browser CONVERTS the HTML into a structured, tree-like
object in memory. This structure is what JavaScript can work with.

That structure is called the DOM.

================================================================================
3. THE DOM — EXPLAINED WORD BY WORD
================================================================================

DOM stands for:

  D — Document
  O — Object
  M — Model

Let's understand each word on its own.

─────────────────────────────────
D — DOCUMENT
─────────────────────────────────

In browser terms, the entire webpage is called a "document".

When you type:

    document

in JavaScript, you're referring to:

  "The current webpage that is open in the browser."

That's it. document = the whole page.

─────────────────────────────────
O — OBJECT
─────────────────────────────────

JavaScript treats every single HTML element as an OBJECT.

You know what objects look like in JavaScript:

    const person = {
      name: "Alice",
      age: 20,
    };

Well, the browser treats your HTML elements the same way. Internally,
the browser looks at this:

    <h1 id="heading">Hello</h1>

And creates something like this JavaScript object:

    {
      tagName: "H1",
      id: "heading",
      innerText: "Hello",
      style: { color: "", fontSize: "", ... },
      // ... many more properties
    }

It's not EXACTLY like this under the hood, but this is a perfect mental model.

Since it's an object, you can read its properties:

    element.innerText        →  "Hello"
    element.id               →  "heading"

And you can change them:

    element.innerText = "Welcome";
    element.style.color = "red";

─────────────────────────────────
M — MODEL
─────────────────────────────────

A "model" is a REPRESENTATION of something real.

Examples:
  - A toy car is a MODEL of a real car.
  - A map is a MODEL of a real city.
  - An architect's floor plan is a MODEL of a real building.

Similarly, the DOM is a MODEL (representation) of your HTML document.
It lives in the browser's memory. It's the browser's working copy of your page.

─────────────────────────────────
PUTTING IT ALL TOGETHER
─────────────────────────────────

  D — Document   →  Your webpage
  O — Object     →  Every HTML element becomes a JavaScript object
  M — Model      →  A structured representation of the page in memory

  DOM = The browser's in-memory, object-based representation of your webpage.

================================================================================
4. THE DOM TREE
================================================================================

The browser converts your HTML into a TREE structure. Here's why it's a tree:
HTML elements are nested inside each other, just like branches on a tree.

YOUR HTML:

    <!DOCTYPE html>
    <html>
      <body>
        <h1>Hello</h1>
        <button>Click Me</button>
      </body>
    </html>

THE DOM TREE THE BROWSER CREATES:

    Document
       │
      html
       │
      body
    ┌──┴──────────┐
    │             │
   h1           button
    │             │
  Hello        Click Me

Every HTML tag becomes a NODE in the DOM tree.
Text inside tags also becomes its own node (a "text node").

─────────────────────────────────
FAMILY TREE ANALOGY
─────────────────────────────────

Think of the DOM like a family tree:

    Grandfather
         │
       Father
         │
    ─────┴─────
    │          │
   You      Brother

Each person has relationships:
  - Parent (who they came from)
  - Children (who came from them)
  - Siblings (who share the same parent)

The DOM works the same way:

    html
      │
    body           ← body is a child of html
      │             ← h1 and button are children of body
    ──┴──────────    ← h1 and button are siblings
    │            │
   h1         button

  - html is the PARENT of body
  - body is the PARENT of h1 and button
  - h1 and button are SIBLINGS
  - h1 and button are CHILDREN of body

This parent/child/sibling language is used everywhere in React too!

LARGER EXAMPLE:

HTML:

    <ul>
      <li>Apple</li>
      <li>Mango</li>
    </ul>

DOM Tree:

    Document
        │
       html
        │
       body
        │
        ul
     ┌──┴──┐
     │     │
    li     li
     │      │
  Apple   Mango

Every tag = a node. Every piece of text = a text node.
Together they form the complete DOM tree.

================================================================================
5. WHY DO WE NEED THE DOM?
================================================================================

SCENARIO: You have a page like this:

    <h1>Hello</h1>
    <button>Change Text</button>

The user clicks the button.
You want the heading to change from "Hello" to "Welcome".

QUESTION: Can JavaScript open the HTML file on disk and rewrite it?

❌ NO.
JavaScript running in the browser has NO access to files on your computer.
It cannot open, read, or edit your HTML file.

SOLUTION: The browser already made a copy — the DOM!

JavaScript can access and modify the DOM (the browser's in-memory copy),
and the browser immediately updates what you see on screen.

    HTML file on disk   →  Never touched by JavaScript
    DOM in memory       →  JavaScript reads and changes this
    Browser screen      →  Automatically updates when DOM changes

================================================================================
6. THE HTML FILE vs THE DOM — THE KEY DIFFERENCE
================================================================================

This is where MOST beginners have a misconception. Let's fix it now.

EXAMPLE:

HTML file on disk:

    <h1 id="heading">Hello</h1>

JavaScript runs:

    const heading = document.getElementById("heading");
    heading.innerText = "Welcome";

QUESTION 1: Did the HTML file on disk change to <h1>Welcome</h1>?
ANSWER: ❌ NO. The HTML file still says: <h1 id="heading">Hello</h1>

QUESTION 2: What changed?
ANSWER: ✅ The DOM in memory changed. The browser updated the screen.

REAL LIFE ANALOGY:

Imagine a school.
  - The ATTENDANCE REGISTER in the school office = HTML file (original)
  - The teacher's COPY in the classroom = the DOM (browser's working copy)

When a student is absent:
  - The teacher updates their CLASSROOM COPY
  - They don't run to the office and change the original register

Similarly:
  - JavaScript updates the DOM (classroom copy)
  - The HTML file on disk (office register) is untouched

And the browser shows whatever is in the DOM — the teacher's copy.

IMPORTANT RULE TO REMEMBER:
  ✅ JavaScript changes the DOM.
  ✅ The browser updates the screen based on the DOM.
  ❌ The original HTML file is never changed by JavaScript.

7. DOM MANIPULATION — getElementById
================================================================================

Now that we understand the DOM, let's start USING it.

To change something on the page, you first need to FIND the element.
The most common way is getElementById().

HOW TO SELECT AN ELEMENT:

HTML:

    <h1 id="heading">Hello</h1>

JavaScript:

    document.getElementById("heading")

READ THIS LIKE ENGLISH:

    document               →  The current webpage
    .getElementById(...)   →  Find the element whose id is...
    "heading"              →  ...this id

RESULT: JavaScript returns the h1 element as a JavaScript OBJECT.
You can then read it, change it, style it — whatever you need.

STEP-BY-STEP BREAKDOWN (teach it piece by piece):

  Step 1:
    document
    → "What is document?"
    → The current webpage.

  Step 2:
    document.getElementById("heading")
    → "What will this return?"
    → The h1 element as a DOM object.

  Step 3:
    document.getElementById("heading").innerText
    → "What are we accessing?"
    → The text content inside that h1.

  Step 4:
    document.getElementById("heading").innerText = "Welcome";
    → "What are we doing?"
    → Replacing the text "Hello" with "Welcome".

BROWSER'S THOUGHT PROCESS:

    Go to the webpage
         ↓
    Find the element with id = "heading"
         ↓
    Access its innerText property
         ↓
    Set it to "Welcome"
         ↓
    Update the screen

PRACTICAL EXAMPLE:

HTML:

    <!DOCTYPE html>
    <html>
      <body>
        <h1 id="heading">Hello</h1>
        <button id="btn">Change Text</button>

        <script>
          const heading = document.getElementById("heading");
          const btn = document.getElementById("btn");

          btn.addEventListener("click", function () {
            heading.innerText = "Welcome to JavaScript!";
          });
        </script>
      </body>
    </html>

Click the button → heading changes instantly. The HTML file? Untouched.

8. STORING ELEMENTS IN VARIABLES — AND WHY IT MATTERS
================================================================================

Look at these two approaches. Both work. One is much better.

─────────────────────────────────
APPROACH 1: Without a variable (❌ Not recommended)
─────────────────────────────────

    document.getElementById("heading").innerText = "React";
    document.getElementById("heading").style.color = "red";
    document.getElementById("heading").style.fontSize = "40px";
    document.getElementById("heading").style.backgroundColor = "yellow";

Notice the problem?

You're asking the browser to SEARCH the entire DOM for "heading" FOUR times.
That's wasteful. Every getElementById() call is a search operation.

─────────────────────────────────
APPROACH 2: With a variable (✅ Recommended)
─────────────────────────────────

    const heading = document.getElementById("heading");

    heading.innerText = "React";
    heading.style.color = "red";
    heading.style.fontSize = "40px";
    heading.style.backgroundColor = "yellow";

The browser searches ONCE. Then you reuse the same object.
Cleaner, faster, and much easier to read.

─────────────────────────────────
LIBRARY ANALOGY
─────────────────────────────────

WITHOUT a variable — going to the shelf every time:

    Go to Shelf 5 → Pick book → Put it back
    Go to Shelf 5 → Pick book → Put it back
    Go to Shelf 5 → Pick book → Put it back
    Go to Shelf 5 → Pick book → Put it back

Very inefficient.

WITH a variable — grab once, use many times:

    Go to Shelf 5 → Pick the book → Keep it in your hand
    Read Page 10 → Highlight Page 20 → Bookmark Page 30 → Take notes

One trip. Many uses. That's a variable.

─────────────────────────────────
BENEFITS OF STORING IN A VARIABLE
─────────────────────────────────

  ✅ Avoid repeated DOM searches
  ✅ Cleaner, more readable code
  ✅ Easier to debug (one place to check)
  ✅ Slightly better performance (especially with many operations)

─────────────────────────────────
INTERVIEW TIP
─────────────────────────────────

  Q: "Why do we store DOM elements in variables?"

  A: "To avoid repeatedly searching the DOM for the same element.
      Storing it in a variable means we search once and reuse the
      reference. This improves readability, maintainability, and
      can provide a small performance benefit."

9. innerText — CHANGING TEXT CONTENT
================================================================================

innerText is used to GET or SET the plain text inside an element.

GETTING THE TEXT:

    <h1 id="heading">Hello</h1>

    const heading = document.getElementById("heading");
    console.log(heading.innerText);   // "Hello"

SETTING (CHANGING) THE TEXT:

    heading.innerText = "Welcome";

    // The browser now shows: Welcome

PRACTICAL EXAMPLE — Button changes text:

    <h1 id="title">Hello, World!</h1>
    <button id="btn">Update Heading</button>

    const title = document.getElementById("title");
    const btn = document.getElementById("btn");

    btn.addEventListener("click", function () {
      title.innerText = "Welcome to JavaScript!";
    });

DYNAMIC TEXT — using a variable:

    const userName = "Alice";
    title.innerText = "Hello, " + userName + "!";
    // OR with template literals:
    title.innerText = `Hello, ${userName}!`;

    // Browser shows: Hello, Alice!

10. innerHTML — INSERTING HTML CONTENT
================================================================================

innerHTML is like innerText, but it interprets HTML tags.
Use it when you need to insert formatted content, not just plain text.

EXAMPLE:

    const heading = document.getElementById("heading");

    // innerText — treats everything as plain text
    heading.innerText = "<i>Hello</i>";
    // Browser shows literally: <i>Hello</i>

    // innerHTML — parses and renders the HTML
    heading.innerHTML = "<i>Hello</i>";
    // Browser shows: Hello (in italics)

MORE EXAMPLES:

    heading.innerHTML = "<strong>Bold Text</strong>";
    // Browser shows: Bold Text (in bold)

    heading.innerHTML = "Hello <span style='color:red'>World</span>";
    // Browser shows: Hello World (with "World" in red)

INSERTING A LIST DYNAMICALLY:

    const ul = document.getElementById("list");

    ul.innerHTML = `
      <li>Apple</li>
      <li>Banana</li>
      <li>Cherry</li>
    `;

─────────────────────────────────
innerText vs innerHTML — SIDE BY SIDE
─────────────────────────────────

    element.innerText = "<b>Hello</b>";
    // Shows on screen: <b>Hello</b>   (plain text, no formatting)

    element.innerHTML = "<b>Hello</b>";
    // Shows on screen: Hello          (bold, HTML is rendered)

  ┌────────────────┬──────────────────────────────────┬──────────────────────┐
  │                │ innerText                        │ innerHTML            │
  ├────────────────┼──────────────────────────────────┼──────────────────────┤
  │ Interprets HTML│ No — shows as plain text         │ Yes — renders tags   │
  │ Use case       │ Safe text content                │ HTML content         │
  │ Safety         │ Safer (prevents XSS attacks)     │ Use carefully        │
  └────────────────┴──────────────────────────────────┴──────────────────────┘

⚠️ SECURITY NOTE:
  Never put user input directly into innerHTML without sanitizing it first.
  This can lead to security vulnerabilities (XSS attacks).
  For user-generated text, always use innerText.

11. style — CHANGING CSS WITH JAVASCRIPT
================================================================================

The style property lets you change CSS directly on an element.
style is an OBJECT on every DOM element.

BASIC USAGE:

    const heading = document.getElementById("heading");

    heading.style.color = "red";
    heading.style.backgroundColor = "yellow";
    heading.style.fontSize = "40px";
    heading.style.fontWeight = "bold";
    heading.style.textAlign = "center";
    heading.style.display = "none";       // hides the element
    heading.style.display = "block";      // shows it again

NOTICE THE NAMING: CSS uses kebab-case. JavaScript uses camelCase.

    CSS Property        JavaScript Property
    ─────────────────────────────────────────
    background-color  → backgroundColor
    font-size         → fontSize
    font-weight       → fontWeight
    text-align        → textAlign
    border-radius     → borderRadius
    z-index           → zIndex

VISUALIZING THE style OBJECT:

    heading
      │
    style  ← this is also an object
      │
    ┌──────────────────────┐
    │ color: ""            │
    │ backgroundColor: ""  │
    │ fontSize: ""         │
    │ fontWeight: ""       │
    │ ...                  │
    └──────────────────────┘

PRACTICAL EXAMPLE — Styled button click:

    <h1 id="heading">Hello</h1>
    <button id="styleBtn">Style It</button>

    const heading = document.getElementById("heading");
    const styleBtn = document.getElementById("styleBtn");

    styleBtn.addEventListener("click", function () {
      heading.style.color = "white";
      heading.style.backgroundColor = "#4f46e5";
      heading.style.padding = "10px 20px";
      heading.style.borderRadius = "8px";
    });

HIDE AND SHOW EXAMPLE:

    let isVisible = true;

    const paragraph = document.getElementById("para");
    const toggleBtn = document.getElementById("toggleBtn");

    toggleBtn.addEventListener("click", function () {
      if (isVisible) {
        paragraph.style.display = "none";
        toggleBtn.innerText = "Show";
      } else {
        paragraph.style.display = "block";
        toggleBtn.innerText = "Hide";
      }
      isVisible = !isVisible;
    });

12. EVENTS & addEventListener
================================================================================

An EVENT is something that HAPPENS in the browser — usually triggered by the user.

COMMON EVENTS:
  ┌────────────────────┬───────────────────────────────────────────┐
  │ Event              │ When it fires                             │
  ├────────────────────┼───────────────────────────────────────────┤
  │ "click"            │ User clicks an element                    │
  │ "mouseover"        │ Mouse moves over an element               │
  │ "mouseout"         │ Mouse leaves an element                   │
  │ "keydown"          │ User presses a key                        │
  │ "keyup"            │ User releases a key                       │
  │ "change"           │ Input value changes                       │
  │ "submit"           │ Form is submitted                         │
  │ "load"             │ Page finishes loading                     │
  └────────────────────┴───────────────────────────────────────────┘

─────────────────────────────────
OLD WAY (avoid this)
─────────────────────────────────

    <!-- Mixes HTML and JavaScript — bad practice -->
    <button onclick="changeText()">Click</button>

    function changeText() {
      heading.innerText = "React";
    }

─────────────────────────────────
MODERN WAY — addEventListener (use this always)
─────────────────────────────────

HTML:
    <button id="btn">Click</button>

JavaScript:
    const btn = document.getElementById("btn");

    btn.addEventListener("click", function () {
      heading.innerText = "React";
    });

READ IT LIKE ENGLISH:

    btn.addEventListener("click", function() { ... })
     ↑         ↑            ↑          ↑
  element   listen for   this event   run this function

= "Hey button, listen for the 'click' event. When it happens, run this function."

─────────────────────────────────
WHY addEventListener IS BETTER
─────────────────────────────────

  ✅ Keeps HTML and JavaScript SEPARATE (clean code)
  ✅ You can attach MULTIPLE events to the same element
  ✅ You can add and remove event listeners programmatically
  ✅ Works with any event type

MULTIPLE EVENT LISTENERS ON ONE ELEMENT:

    btn.addEventListener("click", function () {
      heading.innerText = "Clicked!";
    });

    btn.addEventListener("mouseover", function () {
      btn.style.backgroundColor = "blue";
    });

    btn.addEventListener("mouseout", function () {
      btn.style.backgroundColor = "";
    });

─────────────────────────────────
THE EVENT OBJECT
─────────────────────────────────

Every event listener automatically receives an EVENT OBJECT.
It contains information about what happened.

    btn.addEventListener("click", function (event) {
      console.log(event.type);     // "click"
      console.log(event.target);   // the button element
    });

For keyboard events:

    document.addEventListener("keydown", function (event) {
      console.log(event.key);      // "a", "Enter", "ArrowUp", etc.
    });

13. 🎯 DOM PROJECT: COUNTER
================================================================================

Let's build a counter. This single project uses EVERYTHING we learned today.

─────────────────────────────────────────────────────────────────────────────
FILE: counter.html
─────────────────────────────────────────────────────────────────────────────

    <!DOCTYPE html>
    <html lang="en">
    <head>
      <meta charset="UTF-8" />
      <title>DOM Counter</title>
      <style>
        body {
          font-family: sans-serif;
          display: flex;
          flex-direction: column;
          align-items: center;
          padding: 60px;
          background: #f0f4ff;
        }
        h1 {
          font-size: 80px;
          margin: 0;
          color: #4f46e5;
        }
        .buttons {
          display: flex;
          gap: 16px;
          margin-top: 30px;
        }
        button {
          padding: 14px 28px;
          font-size: 20px;
          border: none;
          border-radius: 8px;
          cursor: pointer;
          font-weight: bold;
        }
        #decrement { background: #fee2e2; color: #dc2626; }
        #reset     { background: #e5e7eb; color: #333; }
        #increment { background: #dcfce7; color: #16a34a; }
      </style>
    </head>
    <body>

      <p>Counter App</p>
      <h1 id="count">0</h1>

      <div class="buttons">
        <button id="decrement">− Decrement</button>
        <button id="reset">Reset</button>
        <button id="increment">+ Increment</button>
      </div>

      <script>
        // Step 1: Declare the counter variable
        let count = 0;

        // Step 2: Select all elements ONCE and store in variables
        const countDisplay = document.getElementById("count");
        const incrementBtn = document.getElementById("increment");
        const decrementBtn = document.getElementById("decrement");
        const resetBtn     = document.getElementById("reset");

        // Step 3: Add event listeners

        incrementBtn.addEventListener("click", function () {
          count++;                              // increase count by 1
          countDisplay.innerText = count;       // update the DOM
        });

        decrementBtn.addEventListener("click", function () {
          count--;                              // decrease count by 1
          countDisplay.innerText = count;       // update the DOM
        });

        resetBtn.addEventListener("click", function () {
          count = 0;                            // reset to 0
          countDisplay.innerText = count;       // update the DOM
        });
      </script>

    </body>
    </html>

─────────────────────────────────
WHAT HAPPENS WHEN INCREMENT IS CLICKED:
─────────────────────────────────

    Button Click
         ↓
    "click" event fires
         ↓
    addEventListener callback runs
         ↓
    count++ (count goes from 0 to 1)
         ↓
    countDisplay.innerText = count  (DOM updates to show "1")
         ↓
    Browser repaints the screen
         ↓
    User sees: 1

─────────────────────────────────
CONCEPTS USED IN THIS PROJECT:
─────────────────────────────────

  ✅ getElementById — selecting 4 elements
  ✅ Variables — storing elements for reuse
  ✅ let — a changeable variable for count
  ✅ addEventListener — listening for clicks
  ✅ innerText — updating what the user sees
  ✅ JavaScript operators — count++, count--

14. 🌉 THE BRIDGE TO REACT
================================================================================

Now that you understand DOM manipulation, let's talk about WHY React exists.

─────────────────────────────────
THE PROBLEM WITH PLAIN DOM
─────────────────────────────────

Imagine a shopping cart page. When the user adds an item, you need to update:

    cartCount.innerText = count;
    totalPrice.innerText = price;
    cartBadge.innerText = count;
    notification.innerText = "Item added!";
    itemList.innerHTML = renderItems();
    checkoutTotal.innerText = price;
    emptyMessage.style.display = "none";

That's 7 manual DOM updates for ONE user action.
A real app might have 50+ elements that need updating.
This becomes impossible to manage.

And if you forget to update even ONE element? Your UI shows stale, wrong data.

─────────────────────────────────
HOW REACT SOLVES THIS
─────────────────────────────────

In React, you only change the STATE. React updates the DOM for you.

PLAIN JAVASCRIPT (manual DOM):

    let count = 0;
    const countDisplay = document.getElementById("count");

    button.addEventListener("click", function () {
      count++;
      countDisplay.innerText = count;   // ← you update DOM manually
    });

REACT (automatic DOM):

    const [count, setCount] = useState(0);

    <button onClick={() => setCount(count + 1)}>
      Increment
    </button>

    <h1>{count}</h1>

Notice what's MISSING in React:
  ❌ No document.getElementById()
  ❌ No .innerText
  ❌ No manual DOM manipulation at all

You just change the state. React figures out what changed in the DOM
and updates only those parts automatically. This is called the
VIRTUAL DOM — React's internal system for efficient updates.

─────────────────────────────────
THE BIG PICTURE — FLOW COMPARISON
─────────────────────────────────

PLAIN JAVASCRIPT:
    User Action → You update DOM manually → Browser repaints

REACT:
    User Action → You update STATE → React updates DOM → Browser repaints

The difference: in React, YOU don't touch the DOM at all.
React is the middleman that handles all DOM updates for you.

─────────────────────────────────
WHY THIS DOM KNOWLEDGE STILL MATTERS
─────────────────────────────────

Even though React handles the DOM for you, understanding the DOM means:
  ✅ You understand WHY React exists and what problem it solves
  ✅ You understand what happens under the hood
  ✅ You can debug issues more effectively
  ✅ You can use DOM when React isn't available (plain JS projects)
  ✅ You understand event handling (onClick in React = click in DOM)
  ✅ You understand why state triggers re-renders (DOM updates)

                         📝 COMPLETE DOM CHEAT SHEET
================================================================================

SELECTING ELEMENTS:
  document.getElementById("id")         → finds one element by id
  document.querySelector(".class")      → finds first match by CSS selector
  document.querySelectorAll(".class")   → finds all matches (NodeList)

CHANGING CONTENT:
  element.innerText = "new text"        → change plain text
  element.innerHTML = "<b>bold</b>"     → change HTML content

CHANGING STYLE:
  element.style.color = "red"
  element.style.backgroundColor = "blue"
  element.style.fontSize = "24px"
  element.style.display = "none"        → hide element
  element.style.display = "block"       → show element

EVENTS:
  element.addEventListener("click",      function() { ... })
  element.addEventListener("mouseover",  function() { ... })
  element.addEventListener("keydown",    function(e) { console.log(e.key) })
  element.addEventListener("change",     function(e) { console.log(e.target.value) })

FULL FLOW:
  HTML File → Browser Reads → DOM Tree Created → JS Accesses DOM
  → JS Changes DOM → Browser Updates Screen

KEY RULES:
  ✅ JavaScript changes the DOM, NOT the HTML file
  ✅ Store elements in variables to avoid repeated searches
  ✅ Use addEventListener (modern) not onclick="" (old)
  ✅ Use innerText for plain text, innerHTML for HTML content
  ✅ CSS uses kebab-case (font-size), JS style uses camelCase (fontSize)
