1. WHAT IS A SIDE EFFECT?
================================================================================

In React, a component's JOB is simple:
  → Take props/state as INPUT
  → Return JSX (UI) as OUTPUT

That's it. Everything inside the render is PURE — same input, same output.

A SIDE EFFECT is anything that happens OUTSIDE of rendering the UI.
It is any code that reaches outside the component to the world.

EXAMPLES OF SIDE EFFECTS:
──────────────────────────
  ✅ Calling an API (fetch data from a server)
  ✅ Setting a timer (setTimeout, setInterval)
  ✅ Adding event listeners (window.addEventListener)
  ✅ Updating the document title (document.title = "Hello")
  ✅ Reading/Writing localStorage
  ✅ Manually touching the real DOM

WHY ARE SIDE EFFECTS "PROBLEMATIC"?
─────────────────────────────────────
React renders your component many times.
If you put an API call directly inside the component body (not inside
useEffect), it will run EVERY SINGLE TIME React re-renders — which could
be hundreds of times. This is wasteful and causes bugs.

EXAMPLE OF THE PROBLEM (WRONG WAY):
──────────────────────────────────────
  function App() {
    // ❌ WRONG — this runs every re-render
    fetch("https://api.example.com/users")
      .then(res => res.json())
      .then(data => console.log(data));

    return <div>Hello</div>;
  }

This will call the API endlessly. useEffect fixes this.

================================================================================
2. WHY DO WE NEED useEffect?
================================================================================

useEffect is a special React hook that lets you:
  → Run code AFTER the component renders
  → Control WHEN that code runs (once, every render, or on specific changes)
  → Clean up after yourself when the component is removed

Think of useEffect as saying:
  "React, after you finish painting the screen — go do THIS."

WITHOUT useEffect:
  - Side effects run during rendering → causes infinite loops, bugs, slowness

WITH useEffect:
  - Side effects run AFTER rendering → safe, controlled, predictable

================================================================================
3. WHAT PROBLEM DOES useEffect SOLVE?
================================================================================

PROBLEM 1 — Running code at the right time
   React needs to paint the UI first, THEN do background work.
   useEffect ensures your code runs AFTER React is done rendering.

PROBLEM 2 — Preventing infinite loops
   If you update state inside a component body, it re-renders,
   which updates state again, which re-renders → INFINITE LOOP.
   useEffect lets you safely update state without looping.

PROBLEM 3 — Fetching data once
   You want to call an API once when the page loads — not every time
   a button is clicked or something changes. useEffect with [] does this.

PROBLEM 4 — Cleaning up
   If you add an event listener, you must remove it when the component
   disappears. useEffect  provides a cleanup function for this.

4. useEffect() — SYNTAX & HOW IT WORKS
================================================================================

IMPORT IT FIRST:
  import { useState, useEffect } from "react";

BASIC SYNTAX:
  useEffect(() => {
    
    // Your side effect code goes here
  }, [dependency array]);

useEffect takes TWO arguments:
  1. A FUNCTION — the code you want to run (the side effect)
  2. A DEPENDENCY ARRAY — controls WHEN the code runs

─────────────────────────────────────────────────────────
EXAMPLE 1 — Update document title when count changes
─────────────────────────────────────────────────────────
  import { useState, useEffect } from "react";

  function Counter() {
    const [count, setCount] = useState(0);

    useEffect(() => {
      document.title = `You clicked ${count} times`;
    }, [count]); // runs every time 'count' changes

    return (
      <div>
        <p>Count: {count}</p>
        <button onClick={() => setCount(count + 1)}>Click Me</button>
      </div>
    );
  }

  // Every time the button is clicked, the browser tab title updates.

─────────────────────────────────────────────────────────
EXAMPLE 2 — Run code once when component mounts
─────────────────────────────────────────────────────────
  useEffect(() => {
    console.log("Component appeared on screen!");
  }, []); // empty array = run ONCE only

  // This is perfect for fetching initial data from an API.

================================================================================
5. DEPENDENCY ARRAY — THE MOST IMPORTANT PART
================================================================================

The dependency array is the second argument to useEffect.
It tells React WHEN to run your effect.

There are 3 cases:

─────────────────────────────────────────────────────
CASE 1: No dependency array → runs after EVERY render
─────────────────────────────────────────────────────
  useEffect(() => {
    console.log("Runs every render");
  });
  // ⚠️ Use this carefully — can cause performance issues

─────────────────────────────────────────────────────
CASE 2: Empty array [] → runs ONCE (on mount)
─────────────────────────────────────────────────────
  useEffect(() => {
    console.log("Runs only once — when component first appears");
    fetchData(); // fetch API data here
  }, []);
  // ✅ Best for initial API calls

─────────────────────────────────────────────────────
CASE 3: Array with values [a, b] → runs when a or b changes
─────────────────────────────────────────────────────
  useEffect(() => {
    console.log("Runs when 'userId' changes");
    fetchUserById(userId);
  }, [userId]);
  // ✅ Best when you want to react to specific state/prop changes

ANALOGY:
  Think of it like a smoke detector.
  - No array → alarm goes off all the time (every movement)
  - []       → alarm is installed once and stays quiet
  - [smoke]  → alarm only goes off when it detects smoke

6. WHAT IS AN API?
================================================================================

API = Application Programming Interface

In simple words: An API is a way for two programs to talk to each other.

REAL-WORLD ANALOGY:
  You go to a restaurant.
  You don't go into the kitchen to cook your food.
  You give your ORDER to the WAITER.
  The waiter goes to the kitchen and brings back your food.

  In this analogy:
    YOU         = your React app
    WAITER      = the API
    KITCHEN     = the server / database

A REST API is the most common type of web API.
It works over HTTP and returns data (usually in JSON format).

POPULAR FREE APIS FOR PRACTICE:
  https://jsonplaceholder.typicode.com/users     → fake user data
  https://jsonplaceholder.typicode.com/posts     → fake post data
  https://api.github.com/users                   → real GitHub users

JSON EXAMPLE (what an API returns):
  {
    "id": 1,
    "name": "Leanne Graham",
    "email": "Sincere@april.biz",
    "phone": "1-770-736-0988"
  }

JSON = JavaScript Object Notation
It looks like a JavaScript object but it's just TEXT (a string).
We must convert it using .json() before we can use it.

================================================================================
7. WHAT IS fetch()?
================================================================================

fetch() is a built-in browser function that lets you make HTTP requests.
It's how your React app talks to an API (a server).

BASIC SYNTAX:
  fetch("https://jsonplaceholder.typicode.com/users")

That's it. Just pass the URL as a string.

But fetch() does NOT return data directly.
It returns a PROMISE.

HOW IT WORKS STEP BY STEP:
  Step 1: fetch() sends a request to the URL
  Step 2: The server processes the request
  Step 3: The server sends back a Response
  Step 4: We call .json() to convert the response body to real JavaScript data
  Step 5: Now we have our array/object to use

FETCH WITH .then() (Promise chaining):
  fetch("https://jsonplaceholder.typicode.com/users")
    .then(response => response.json())   // Step 4: convert to JS object
    .then(data => console.log(data))     // Step 5: use the data
    .catch(error => console.log(error)); // catch any errors

================================================================================
8. WHY DOES fetch() RETURN A PROMISE?
================================================================================

A PROMISE represents a value that is NOT available yet, but will be in the future.

ANALOGY:
  You order a pizza online.
  You get a RECEIPT (the promise).
  The pizza isn't here yet, but it WILL be.
  When it arrives → the promise is "resolved" (success)
  If they cancel it → the promise is "rejected" (error)

WHY IS THIS NEEDED?
  JavaScript runs line by line (synchronously).
  Network requests take TIME — milliseconds to seconds.
  If JavaScript waited for each request to finish, the whole page would FREEZE.
  Promises let JavaScript say: "Go fetch this, and call me when it's ready."
  Meanwhile, JavaScript keeps running other code.

PROMISE STATES:
  ⏳ Pending   → request has been sent, waiting for response
  ✅ Fulfilled → response received successfully
  ❌ Rejected  → something went wrong (network error, server error, etc.)

9. WHY DO WE USE async/await?
================================================================================

async/await is a cleaner, more readable way to work with Promises.
Instead of chaining .then().then().then(), we write code that LOOKS synchronous.

WITHOUT async/await (Promise chaining — harder to read):
  fetch("https://jsonplaceholder.typicode.com/users")
    .then(res => res.json())
    .then(data => {
      setUsers(data);
    })
    .catch(err => {
      console.log(err);
    });

WITH async/await (same thing — much cleaner):
  async function fetchUsers() {
    const res = await fetch("https://jsonplaceholder.typicode.com/users");
    const data = await res.json();
    setUsers(data);
  }

WHAT DO async AND await MEAN?

  async → marks a function as asynchronous.
          It tells JavaScript: "This function will do async work."
          An async function always returns a Promise.

  await → pauses execution INSIDE the async function until the Promise resolves.
          It says: "Wait here until this is done, then continue."
          NOTE: await only pauses the async function — NOT the whole app.

RULE: You can only use await INSIDE an async function.

─────────────────────────────────────────────────────────
FULL EXAMPLE with error handling using try/catch:
─────────────────────────────────────────────────────────
  async function fetchUsers() {
    try {
      const response = await fetch("https://jsonplaceholder.typicode.com/users");

      if (!response.ok) {
        throw new Error("Server error: " + response.status);
      }

      const data = await response.json();
      setUsers(data);

    } catch (error) {
      console.log("Something went wrong:", error.message);
      setError(error.message);
    }
  }

  // try  → attempt the code
  // catch → if anything goes wrong, handle the error here

10. HOW DO WE DISPLAY A LOADING MESSAGE?
================================================================================

When you call an API, there is a delay before data arrives.
During that time, you should show the user a loading indicator
instead of a blank screen.

HOW IT WORKS:
  1. Create a loading state: const [loading, setLoading] = useState(true)
  2. Set loading to false AFTER data is fetched
  3. Conditionally render a loading message in JSX

EXAMPLE:
──────────
  function App() {
    const [users, setUsers] = useState([]);
    const [loading, setLoading] = useState(true);

    useEffect(() => {
      async function fetchUsers() {
        const res = await fetch("https://jsonplaceholder.typicode.com/users");
        const data = await res.json();
        setUsers(data);
        setLoading(false); // ← flip loading to false when done
      }
      fetchUsers();
    }, []);

    if (loading) {
      return <p>Loading users, please wait...</p>;
    }

    return (
      <ul>
        {users.map(user => (
          <li key={user.id}>{user.name}</li>
        ))}
      </ul>
    );
  }

FLOW:
  Page loads → loading = true → show "Loading..."
  API returns → loading = false → show the users list

11. HOW DO WE RENDER USERS WITH map()?
================================================================================

Once we have our array of users from the API, we use .map() to turn
each user object into a JSX element.

WHAT IS .map()?
  Array.map() loops over each item in an array and returns a NEW array.
  In React, we use it to turn data arrays into JSX arrays.

SIMPLE EXAMPLE:
  const names = ["Ali", "Sara", "John"];
  const items = names.map(name => <li>{name}</li>);
  // items = [ <li>Ali</li>, <li>Sara</li>, <li>John</li> ]

WITH API DATA:
  {users.map(user => (
    <div key={user.id}>
      <h3>{user.name}</h3>
      <p>{user.email}</p>
      <p>{user.phone}</p>
    </div>
  ))}

THE key PROP — VERY IMPORTANT:
  When rendering lists in React, every item MUST have a unique key prop.
  React uses the key to track which items changed, were added, or removed.

  ✅ key={user.id}    → good (unique ID from server)
  ✅ key={user.email} → good if emails are unique
  ❌ key={index}      → bad (index can change when list reorders)

12. CLEANUP IN useEffect
================================================================================

Sometimes your side effect creates something that needs to be REMOVED
when the component is no longer on screen (unmounts).

If you don't clean up:
  - Memory leaks (timers keep running after component is gone)
  - State updates on unmounted components (React warning)
  - Multiple event listeners stacking up

HOW TO CLEANUP:
  Return a function from inside useEffect.
  React will call this function automatically when the component unmounts.

─────────────────────────────────────────────────────────
EXAMPLE 1 — Cleanup a timer
─────────────────────────────────────────────────────────
  useEffect(() => {
    const timer = setInterval(() => {
      console.log("Tick...");
    }, 1000);

    return () => {
      clearInterval(timer); // ← cleanup: stop the timer
      console.log("Timer cleaned up");
    };
  }, []);

─────────────────────────────────────────────────────────
EXAMPLE 2 — Cleanup an event listener
─────────────────────────────────────────────────────────
  useEffect(() => {
    function handleResize() {
      console.log("Window resized:", window.innerWidth);
    }

    window.addEventListener("resize", handleResize);

    return () => {
      window.removeEventListener("resize", handleResize); // ← cleanup
    };
  }, []);

WHEN DOES CLEANUP RUN?
  → When the component is REMOVED from the screen (unmounts)
  → Before the effect runs AGAIN (if dependencies change)

13. PROJECT: USERS API
================================================================================

GOAL: Build a React app that fetches users from a free API and displays
      their name, email, and phone — with a loading state.

API URL: https://jsonplaceholder.typicode.com/users

──────────────────────────────────────────────
FULL CODE — App.jsx
──────────────────────────────────────────────

  import { useState, useEffect } from "react";

  function App() {
    const [users, setUsers]     = useState([]);
    const [loading, setLoading] = useState(true);
    const [error, setError]     = useState(null);

    useEffect(() => {
      async function fetchUsers() {
        try {
          const response = await fetch(
            "https://jsonplaceholder.typicode"
          );

          if (!response.ok) {
            throw new Error("Failed to fetch users");
          }

          const data = await response.json();
          setUsers(data);

        } catch (err) {
          setError(err.message);
        } 
      }

      fetchUsers();
    }, []); // [] = run once when page loads

    // Show loading message
    if (loading) return <p>Loading users...</p>;

    // Show error message
    if (error) return <p style={{ color: "red" }}>Error: {error}</p>;

    // Show users list
    return (
      <div>
        <h1>Users List</h1>
        {users.map(user => (
          <div key={user.id} style={{ border: "1px solid #ccc", margin: "10px", padding: "10px" }}>
            <h3>{user.name}</h3>
            <p>📧 Email: {user.email}</p>
            <p>📞 Phone: {user.phone}</p>
            <p>🌐 Website: {user.website}</p>
          </div>
        ))}
      </div>
    );
  }

  export default App;

──────────────────────────────────────────────
WHAT HAPPENS STEP BY STEP:
──────────────────────────────────────────────
  1. App renders for the first time → shows "Loading users..."
  2. useEffect fires (after render) → fetchUsers() is called
  3. fetch() sends request to the API
  4. API returns 10 user objects as JSON
  5. setUsers(data) → stores users in state
  6. setLoading(false) → triggers re-render
  7. App re-renders → shows the list of users with map()

──────────────────────────────────────────────
UNDERSTANDING THE finally BLOCK:
──────────────────────────────────────────────
  try {
    // attempt this
  } catch (err) {
    // handle errors
  } finally {
    setLoading(false); // ALWAYS runs — even if there's an error
  }

  Without finally:
    If an error occurs, setLoading(false) in the try block is never reached.
    The loading spinner never stops. Use finally to always stop loading.

14. WHAT IS AXIOS?
================================================================================

Axios is a popular JavaScript LIBRARY for making HTTP requests.
It does the same job as fetch(), but with extra benefits.

INSTALL AXIOS:
  npm install axios

WHY USE AXIOS INSTEAD OF fetch()?
───────────────────────────────────────────────────────────────────────────────

  FEATURE                    fetch()              Axios
  ─────────────────────────  ──────────────────   ────────────────────────────
  Built into browser?        ✅ Yes               ❌ No (must install)
  Auto-convert JSON?         ❌ Must call .json()  ✅ Does it automatically
  Auto error on 4xx/5xx?     ❌ Must check res.ok  ✅ Automatically throws error
  Request timeout support?   ❌ Complicated        ✅ Easy: { timeout: 5000 }
  Intercept requests?        ❌ No                ✅ Yes (add auth headers, etc.)
  Cancel requests?           ❌ Complex            ✅ Easy with AbortController
  Cleaner syntax?            Somewhat             ✅ Much cleaner

IMPORT AXIOS:
  import axios from "axios";

AXIOS METHODS:
  axios.get(url)           → GET  request  (read data)
  axios.post(url, data)    → POST request  (send/create data)
  axios.put(url, data)     → PUT  request  (update data)
  axios.delete(url)        → DELETE request (remove data)

15. AXIOS GET REQUEST
================================================================================

A GET request is used to READ / FETCH data from a server.
It does NOT change anything on the server.

WITH fetch():
  const res = await fetch("https://jsonplaceholder.typicode.com/users");
  const data = await res.json(); // ← must manually convert

WITH Axios (cleaner):
  const res = await axios.get("https://jsonplaceholder.typicode.com/users");
  const data = res.data; // ← Axios already converts JSON automatically

NOTE: Axios stores the actual data inside res.DATA (not res itself).

─────────────────────────────────────────────────────────
FULL EXAMPLE — GET request with Axios
─────────────────────────────────────────────────────────
  import { useState, useEffect } from "react";
  import axios from "axios";

  function App() {
    const [users, setUsers]     = useState([]);
    const [loading, setLoading] = useState(true);
    const [error, setError]     = useState(null);

    useEffect(() => {
      async function fetchUsers() {
        try {
          const res = await axios.get(
            "https://jsonplaceholder.typicode.com/users"
          );
          setUsers(res.data); // res.data contains the array of users
        } catch (err) {
          setError(err.message);
        } finally {
          setLoading(false);
        }
      }

      fetchUsers();
    }, []);

    if (loading) return <p>Loading...</p>;
    if (error)   return <p style={{ color: "red" }}>Error: {error}</p>;

    return (
      <ul>
        {users.map(user => (
          <li key={user.id}>{user.name} — {user.email}</li>
        ))}
      </ul>
    );
  }

  export default App;

16. AXIOS POST REQUEST
================================================================================

A POST request is used to SEND data to the server (create a new record).
Examples: submitting a registration form, creating a new post, adding a student.

WITH Axios — POST:
  const res = await axios.post(url, dataObject);

  The second argument is the data you want to send (as a JavaScript object).
  Axios automatically converts it to JSON and sets the Content-Type header.

─────────────────────────────────────────────────────────
EXAMPLE — POST new user
─────────────────────────────────────────────────────────
  async function createUser() {
    const newUser = {
      name: "Ahmed Khan",
      email: "ahmed@example.com",
      phone: "0300-1234567"
    };

    try {
      const res = await axios.post(
        "https://jsonplaceholder.typicode.com/users",
        newUser
      );
      console.log("User created:", res.data);
      // res.data contains the newly created user returned by the server
    } catch (err) {
      console.log("Error:", err.message);
    }
  }

NOTE: JSONPlaceholder is a fake API — it will pretend to create the user
      and return a fake response (with id: 11), but nothing is actually saved.
      In a real backend, the data would be stored in a database.

─────────────────────────────────────────────────────────
POST from a Form (Real-World Pattern):
─────────────────────────────────────────────────────────
  function RegisterForm() {
    const [form, setForm] = useState({ name: "", email: "" });
    const [message, setMessage] = useState("");

    function handleChange(e) {
      setForm({ ...form, [e.target.name]: e.target.value });
    }

    async function handleSubmit(e) {
      e.preventDefault();
      try {
        const res = await axios.post(
          "https://jsonplaceholder.typicode.com/users",
          form
        );
        setMessage("User registered: " + res.data.name);
        setForm({ name: "", email: "" }); // reset form
      } catch (err) {
        setMessage("Error: " + err.message);
      }
    }

    return (
      <form onSubmit={handleSubmit}>
        <input
          name="name"
          value={form.name}
          onChange={handleChange}
          placeholder="Full Name"
        />
        <input
          name="email"
          value={form.email}
          onChange={handleChange}
          placeholder="Email"
        />
        <button type="submit">Register</button>
        {message && <p>{message}</p>}
      </form>
    );
  }

17. LOADING STATE WITH AXIOS
================================================================================

Loading state works exactly the same as with fetch().
The pattern is:
  1. loading = true before the request
  2. loading = false in finally (always)
  3. Render loading UI when loading === true

BEST PRACTICE:
  Always use finally to turn off loading — so even if an error
  occurs, the spinner stops.

  const [loading, setLoading] = useState(false); // false = not loading yet

  async function fetchData() {
    setLoading(true); // ← start loading
    try {
      const res = await axios.get("https://...");
      setData(res.data);
    } catch (err) {
      setError(err.message);
    } finally {
      setLoading(false); // ← always stop loading
    }
  }

LOADING UI OPTIONS:
  // Simple text
  if (loading) return <p>Loading...</p>;

  // Spinner using CSS class
  if (loading) return <div className="spinner"></div>;

  // Inline
  {loading ? <p>Loading...</p> : <ul>...</ul>}

18. ERROR HANDLING WITH AXIOS
================================================================================

Axios makes error handling easier than fetch().

WITH fetch() — you must manually check:
  if (!response.ok) {
    throw new Error("Request failed with status: " + response.status);
  }

WITH Axios — it throws automatically:
  If the server returns a 4xx or 5xx status code, Axios automatically throws
  an error. You just need to catch it.

AXIOS ERROR OBJECT:
  err.message          → human-readable message
  err.response         → the server's response (if it replied)
  err.response.status  → HTTP status code (404, 500, etc.)
  err.response.data    → error details from the server
  err.request          → the request that was made (if no response received)

─────────────────────────────────────────────────────────
EXAMPLE — Full error handling
─────────────────────────────────────────────────────────
  async function fetchUser(id) {
    try {
      const res = await axios.get(
        `https://jsonplaceholder.typicode.com/users/${id}`
      );
      setUser(res.data);

    } catch (err) {
      if (err.response) {
        // Server responded with an error status (4xx, 5xx)
        if (err.response.status === 404) {
          setError("User not found.");
        } else {
          setError("Server error: " + err.response.status);
        }
      } else if (err.request) {
        // Request was sent but no response received (network issue)
        setError("Network error. Please check your connection.");
      } else {
        // Something else went wrong
        setError("Error: " + err.message);
      }
    } finally {
      setLoading(false);
    }
  }

HTTP STATUS CODES — QUICK REFERENCE:
  200 → OK (success)
  201 → Created (POST success)
  400 → Bad Request (wrong data sent)
  401 → Unauthorized (not logged in)
  403 → Forbidden (no permission)
  404 → Not Found
  500 → Internal Server Error (server crashed)

19. PROJECT: STUDENT REGISTRATION API

GOAL: Build a Student Registration App that:
  ✅ Fetches all students from the API (GET)
  ✅ Registers a new student via a form (POST)
  ✅ Shows a loading state during requests
  ✅ Shows error messages if something goes wrong
  ✅ Updates the student list after registration

API: We use JSONPlaceholder as a fake backend.
     In a real project, you would replace the URL with your own backend.

  import { useState } from "react";
  import axios from "axios";

  function RegisterForm({ onStudentAdded }) {
    const [form, setForm] = useState({
      name: "",
      email: "",
      phone: "",
      course: ""
    });
    const [loading, setLoading] = useState(false);
    const [message, setMessage] = useState("");
    const [error, setError]     = useState("");

    function handleChange(e) {
      setForm({ ...form, [e.target.name]: e.target.value });
    }

    async function handleSubmit(e) {
      e.preventDefault();
      setLoading(true);
      setMessage("");
      setError("");

      try {
        const res = await axios.post(
          "https://jsonplaceholder.typicode.com/users",
          form
        );

        setMessage(`✅ Student "${res.data.name}" registered successfully!`);
        onStudentAdded(res.data); // tell parent to add student to list
        setForm({ name: "", email: "", phone: "", course: "" }); // reset

      } catch (err) {
        setError("❌ Registration failed: " + err.message);

      } finally {
        setLoading(false);
      }
    }

    return (
      <div style={{ border: "1px solid #4CAF50", padding: "20px", borderRadius: "8px", marginBottom: "30px" }}>
        <h2>Register New Student</h2>

        <form onSubmit={handleSubmit}>
          <div>
            <label>Full Name:</label>
            <input
              name="name"
              value={form.name}
              onChange={handleChange}
              placeholder="e.g. Ali Hassan"
              required
            />
          </div>

          <div>
            <label>Email:</label>
            <input
              type="email"
              name="email"
              value={form.email}
              onChange={handleChange}
              placeholder="e.g. ali@example.com"
              required
            />
          </div>

          <div>
            <label>Phone:</label>
            <input
              name="phone"
              value={form.phone}
              onChange={handleChange}
              placeholder="e.g. 0300-1234567"
            />
          </div>

          <div>
            <label>Course:</label>
            <input
              name="course"
              value={form.course}
              onChange={handleChange}
              placeholder="e.g. React Development"
            />
          </div>

          <button type="submit" disabled={loading}>
            {loading ? "Registering..." : "Register Student"}
          </button>
        </form>

        {message && <p style={{ color: "green" }}>{message}</p>}
        {error   && <p style={{ color: "red" }}>{error}</p>}
      </div>
    );
  }

  export default RegisterForm;

  function StudentList({ students, loading, error }) {
    if (loading) return <p>⏳ Loading students...</p>;
    if (error)   return <p style={{ color: "red" }}>Error: {error}</p>;
    if (students.length === 0) return <p>No students registered yet.</p>;

    return (
      <div>
        <h2>Registered Students ({students.length})</h2>
        {students.map(student => (
          <div
            key={student.id}
            style={{
              border: "1px solid #ddd",
              borderRadius: "8px",
              padding: "12px",
              marginBottom: "10px"
            }}
          >
            <h3>🎓 {student.name}</h3>
            <p>📧 {student.email}</p>
            {student.phone  && <p>📞 {student.phone}</p>}
            {student.course && <p>📚 Course: {student.course}</p>}
          </div>
        ))}
      </div>
    );
  }

  export default StudentList;

FILE: src/App.jsx
─────────────────────────────────────────────────────────────────────────────

  import { useState, useEffect } from "react";
  import axios from "axios";
  import RegisterForm from "./components/RegisterForm";
  import StudentList  from "./components/StudentList";

  function App() {
    const [students, setStudents] = useState([]);
    const [loading, setLoading]   = useState(true);
    const [error, setError]       = useState(null);

    // Fetch existing students when page loads
    useEffect(() => {
      async function fetchStudents() {
        try {
          const res = await axios.get(
            "https://jsonplaceholder.typicode.com/users"
          );
          setStudents(res.data);
        } catch (err) {
          setError(err.message);
        } finally {
          setLoading(false);
        }
      }
      fetchStudents();
    }, []); // [] = only run once

    // Add newly registered student to the list
    function handleStudentAdded(newStudent) {
      setStudents(prev => [newStudent, ...prev]); // add to the top
    }

    return (
      <div style={{ maxWidth: "700px", margin: "0 auto", padding: "20px" }}>
        <h1>🏫 Student Registration System</h1>

        <RegisterForm onStudentAdded={handleStudentAdded} />

        <StudentList
          students={students}
          loading={loading}
          error={error}
        />
      </div>
    );
  }

  export default App;

WHAT THE PROJECT DEMONSTRATES:
─────────────────────────────────────────────────────────────────────────────
  ✅ useEffect with [] → fetch data once on page load
  ✅ useState for students, loading, error, form data
  ✅ Axios GET → fetch existing students
  ✅ Axios POST → register a new student
  ✅ Loading state during fetch and during form submit
  ✅ Error handling for both GET and POST
  ✅ Component splitting → App, RegisterForm, StudentList
  ✅ Props → passing data and functions between components
  ✅ Controlled Form → every input is controlled by state
  ✅ .map() → rendering list of students dynamically
  ✅ Optimistic update → new student appears instantly at top of list

       npm run dev

QUICK REFERENCE — KEY CONCEPTS SUMMARY
================================================================================

  CONCEPT          WHAT IT IS                        WHEN TO USE
  ───────────────  ────────────────────────────────  ──────────────────────────
  Side Effect      Code that reaches outside render  API calls, timers, DOM
  useEffect()      Hook to run side effects safely   After component renders
  []  (dep array)  Run effect once on mount          Initial data fetch
  [val]            Run effect when val changes       Re-fetch on filter change
  fetch()          Browser API for HTTP requests     Simple GET requests
  async/await      Clean syntax for Promises         Any async operation
  .json()          Convert response to JS object     After fetch() response
  try/catch        Handle errors in async code       All async operations
  finally          Always runs after try/catch       Stop loading spinner
  loading state    Boolean tracking request status   Show loading indicator
  .map()           Loop array → return JSX           Render lists
  key prop         Unique ID for list items          Required in .map()
  Axios            HTTP library (better than fetch)  Real projects
  axios.get()      Make GET request                  Fetch/read data
  axios.post()     Make POST request with data       Create/submit data
  res.data         Axios response data               Access returned data
  err.response     Axios error response from server  Check status codes
