1. WHAT ARE PROPS?
================================================================================

On Day 1, we built components that always showed the SAME content:

    function Greeting() {
      return <h1>Hello, Alice!</h1>;
    }

That's great for Alice. But what if 100 students use this app?
You'd have to create 100 different components. That's terrible!

SOLUTION: Props (short for Properties).

Props let you pass DATA into a component from the outside — like giving
a component custom instructions.

ANALOGY:
  Think of a component like a COFFEE MACHINE.
  The machine (component) is always the same.
  But you put in different beans, water, and settings (props) to get
  different results: espresso, latte, cappuccino.

  function CoffeeMachine(props) {
    return <p>Making you a {props.type}!</p>;
  }

  <CoffeeMachine type="latte" />       → Making you a latte!
  <CoffeeMachine type="espresso" />    → Making you a espresso!

Same component, different output. That's the POWER of props.

================================================================================
2. REUSABLE COMPONENTS
================================================================================

Without props, you'd write this:

    function AliceCard() {
      return <div><h2>Alice</h2><p>Age: 20</p></div>;
    }

    function BobCard() {
      return <div><h2>Bob</h2><p>Age: 22</p></div>;
    }

    function CharlieCard() {
      return <div><h2>Charlie</h2><p>Age: 21</p></div>;
    }

With props, you write ONE component:

    function StudentCard(props) {
      return (
        <div>
          <h2>{props.name}</h2>
          <p>Age: {props.age}</p>
        </div>
      );
    }

And use it like this:

    <StudentCard name="Alice" age={20} />
    <StudentCard name="Bob" age={22} />
    <StudentCard name="Charlie" age={21} />

One component. Three different outputs. Reusable!

================================================================================
3. PARENT → CHILD COMMUNICATION
================================================================================

In React, data flows ONE WAY: from Parent DOWN to Child.
This is called "Unidirectional Data Flow".

    Parent Component
        │
        │  passes props
        ▼
    Child Component

The PARENT decides what data to send.
The CHILD receives it and displays it.
The CHILD cannot send data back to the Parent via props (we'll learn events later).

SIMPLE EXAMPLE:

    // ✅ PARENT - App.jsx
    function App() {
      return (
        <div>
          <Greeting name="Alice" />
          <Greeting name="Bob" />
        </div>
      );
    }

    // ✅ CHILD - Greeting.jsx
    function Greeting(props) {
      return <h1>Hello, {props.name}! 👋</h1>;
    }

HOW IT FLOWS:

    App renders → passes name="Alice" to Greeting
    Greeting receives props = { name: "Alice" }
    Greeting displays: Hello, Alice! 👋

IMPORTANT RULE: Props are READ-ONLY.
  The child component can READ props but NEVER MODIFY them.

  ❌ WRONG — never do this in the child:
    function Greeting(props) {
      props.name = "Someone Else";  // ← This will cause an error!
      return <h1>Hello, {props.name}</h1>;
    }

  ✅ CORRECT — just read props:
    function Greeting(props) {
      return <h1>Hello, {props.name}</h1>;
    }

4. DESTRUCTURING PROPS
================================================================================

Instead of writing props.name, props.age, props.email every time,
we can use JavaScript destructuring to pull out values directly.

WITHOUT DESTRUCTURING (works but verbose):

    function StudentCard(props) {
      return (
        <div>
          <h2>{props.name}</h2>
          <p>Age: {props.age}</p>
          <p>Email: {props.email}</p>
        </div>
      );
    }

WITH DESTRUCTURING (cleaner, preferred):

    function StudentCard({ name, age, email }) {
      return (
        <div>
          <h2>{name}</h2>
          <p>Age: {age}</p>
          <p>Email: {email}</p>
        </div>
      );
    }

You can also destructure inside the function body:

    function StudentCard(props) {
      const { name, age, email } = props;
      return (
        <div>
          <h2>{name}</h2>
          <p>Age: {age}</p>
          <p>Email: {email}</p>
        </div>
      );
    }

All three versions do the same thing. The first destructuring style
(in the function parameter) is the most common in real React code.

DEFAULT VALUES WITH DESTRUCTURING:
  You can set a default value in case a prop is not passed:

    function StudentCard({ name, age, role = "Student" }) {
      return (
        <div>
          <h2>{name}</h2>
          <p>Age: {age}</p>
          <p>Role: {role}</p>    ← Uses "Student" if no role prop is given
        </div>
      );
    }

    <StudentCard name="Alice" age={20} />           → Role: Student (default)
    <StudentCard name="Bob" age={22} role="Admin" /> → Role: Admin

================================================================================
5. PASSING DIFFERENT TYPES OF PROPS
================================================================================

You can pass any JavaScript data type as a prop.
The KEY RULE: Strings use quotes " ". Everything else uses { }.

─────────────────────────────────
A. STRINGS
─────────────────────────────────

    <StudentCard name="Alice" city="New York" />

    function StudentCard({ name, city }) {
      return <p>{name} is from {city}</p>;
    }

    Output: Alice is from New York

─────────────────────────────────
B. NUMBERS
─────────────────────────────────

  Numbers must use { } — NOT quotes (quotes make it a string!):

    ❌ WRONG:  <StudentCard age="20" />   ← This is the STRING "20"
    ✅ CORRECT: <StudentCard age={20} />  ← This is the NUMBER 20

    function StudentCard({ name, age }) {
      return (
        <div>
          <p>Name: {name}</p>
          <p>Age: {age}</p>
          <p>Age next year: {age + 1}</p>   ← Math works! (Only if it's a number)
        </div>
      );
    }

    <StudentCard name="Alice" age={20} />

    Output:
      Name: Alice
      Age: 20
      Age next year: 21

─────────────────────────────────
C. BOOLEANS
─────────────────────────────────

  Booleans (true/false) also use { }:

    <StudentCard name="Alice" isEnrolled={true} hasPaid={false} />

  SHORTCUT: Writing the prop name alone means true:

    <StudentCard name="Alice" isEnrolled />    ← isEnrolled={true}

    function StudentCard({ name, isEnrolled, hasPaid }) {
      return (
        <div>
          <h2>{name}</h2>
          <p>Enrolled: {isEnrolled ? "✅ Yes" : "❌ No"}</p>
          <p>Paid: {hasPaid ? "✅ Paid" : "❌ Unpaid"}</p>
        </div>
      );
    }

    Output:
      Alice
      Enrolled: ✅ Yes
      Paid: ❌ Unpaid

─────────────────────────────────
D. ARRAYS
─────────────────────────────────

  Arrays use { } and are rendered using .map():

    <StudentCard
      name="Alice"
      skills={["React", "JavaScript", "CSS"]}
    />

    function StudentCard({ name, skills }) {
      return (
        <div>
          <h2>{name}</h2>
          <h3>Skills:</h3>
          <ul>
            {skills.map((skill) => (
              <li key={skill}>{skill}</li>
            ))}
          </ul>
        </div>
      );
    }

    Output:
      Alice
      Skills:
        • React
        • JavaScript
        • CSS

  ⚠️ NOTE ON key: When rendering lists with .map(), React requires each
  item to have a unique key prop. We explain why in Section 8 (Why map() exists).

─────────────────────────────────
E. OBJECTS
─────────────────────────────────

  Objects use { } and are accessed with dot notation:

    const studentInfo = {
      name: "Alice",
      age: 20,
      grade: "A"
    };

    <StudentCard info={studentInfo} />

    function StudentCard({ info }) {
      return (
        <div>
          <h2>{info.name}</h2>
          <p>Age: {info.age}</p>
          <p>Grade: {info.grade}</p>
        </div>
      );
    }

  OR you can spread the object directly (spread syntax):

    <StudentCard {...studentInfo} />
    // Same as: <StudentCard name="Alice" age={20} grade="A" />

    function StudentCard({ name, age, grade }) {
      return (
        <div>
          <h2>{name}</h2>
          <p>Age: {age}</p>
          <p>Grade: {grade}</p>
        </div>
      );
    }

  PROP TYPES SUMMARY:
  ┌───────────┬──────────────────────────────────────┬──────────────────────────┐
  │ Type      │ Example                              │ Syntax                   │
  ├───────────┼──────────────────────────────────────┼──────────────────────────┤
  │ String    │ name="Alice"                         │ Quotes                   │
  │ Number    │ age={20}                             │ Curly braces             │
  │ Boolean   │ isEnrolled={true} or isEnrolled      │ Curly braces or alone    │
  │ Array     │ skills={["React", "JS"]}             │ Curly braces             │
  │ Object    │ info={{ name: "Alice", age: 20 }}    │ Double curly braces      │
  │ Function  │ onClick={handleClick}                │ Curly braces             │
  └───────────┴──────────────────────────────────────┴──────────────────────────┘

6. THE children PROP
================================================================================

WHAT IS children?
  The children prop is a SPECIAL built-in prop. It automatically contains
  whatever JSX you write BETWEEN the opening and closing tags of a component.

WITHOUT children (self-closing):
    <Button />

WITH children (content between tags):
    <Button>Click Me</Button>
    <Button><span>🚀 Launch</span></Button>

  Everything between <Button> and </Button> becomes props.children.

PRACTICAL EXAMPLE:

    // Button component that wraps any content
    function Button({ children }) {
      return (
        <button style={{ padding: "10px 20px", backgroundColor: "blue", color: "white" }}>
          {children}
        </button>
      );
    }

    // Use it with different content:
    <Button>Click Me</Button>
    <Button>Submit Form</Button>
    <Button>🚀 Launch Rocket</Button>

  Output (three different buttons):
    [ Click Me ]   [ Submit Form ]   [ 🚀 Launch Rocket ]

  The Button component doesn't care WHAT the content is. It just wraps it.

CHILDREN CAN BE ANYTHING:

    <Card>
      <h2>Student Profile</h2>
      <p>Alice, Age 20</p>
      <button>View Details</button>
    </Card>

    function Card({ children }) {
      return (
        <div style={{ border: "1px solid gray", padding: "20px", borderRadius: "8px" }}>
          {children}
        </div>
      );
    }

  The Card wraps everything in a styled box — without knowing what's inside!

WHY IS children USEFUL?
  It's perfect for LAYOUT components: Cards, Modals, Sidebars, Wrappers.
  The layout is fixed, but the CONTENT is flexible.

7. COMPONENT COMPOSITION
================================================================================

WHAT IS COMPOSITION?
  Composition means building complex UIs by combining small, simple components.
  Instead of one giant component, you build many small ones and combine them.

ANALOGY: A car is not built as one solid block. It's built from:
  Engine + Wheels + Seats + Windows + Doors = Car
  Similarly: Header + Sidebar + Content + Footer = Page

EXAMPLE — Building a Student Profile Page:

    // Small components (building blocks)
    function Avatar({ name }) {
      return <div className="avatar">{name[0].toUpperCase()}</div>;
    }

    function Badge({ label }) {
      return <span className="badge">{label}</span>;
    }

    function SkillList({ skills }) {
      return (
        <ul>
          {skills.map((skill) => (
            <li key={skill}>{skill}</li>
          ))}
        </ul>
      );
    }

    // Composed component using all small pieces
    function StudentCard({ name, age, grade, skills }) {
      return (
        <div className="card">
          <Avatar name={name} />
          <h2>{name}</h2>
          <Badge label={`Grade: ${grade}`} />
          <p>Age: {age}</p>
          <SkillList skills={skills} />
        </div>
      );
    }

    // Parent using StudentCard
    function App() {
      return (
        <div>
          <StudentCard
            name="Alice"
            age={20}
            grade="A"
            skills={["React", "CSS", "HTML"]}
          />
          <StudentCard
            name="Bob"
            age={22}
            grade="B+"
            skills={["JavaScript", "Node.js"]}
          />
        </div>
      );
    }

BENEFITS OF COMPOSITION:
  ✅ Each component has one job (easy to understand)
  ✅ Easy to test individual components
  ✅ Easy to reuse components in other parts of the app
  ✅ Easy to update one component without breaking others

8. WHY map() EXISTS (and how it works in React)
================================================================================

PROBLEM WITHOUT map():
  Imagine you have 100 students. Without map(), you'd write:

    function App() {
      return (
        <ul>
          <li>Alice</li>
          <li>Bob</li>
          <li>Charlie</li>
          {/* ... 97 more lines */}
        </ul>
      );
    }

  That's impossible to maintain. Data changes? You update 100 lines manually.

WHAT IS map()?
  map() is a JavaScript array method. It takes each item in an array,
  transforms it, and returns a NEW array.

  BASIC map() EXAMPLE (plain JavaScript):

    const numbers = [1, 2, 3];
    const doubled = numbers.map((num) => num * 2);
    console.log(doubled);   // [2, 4, 6]

  SAME IDEA IN REACT — turning data into JSX:

    const students = ["Alice", "Bob", "Charlie"];

    const listItems = students.map((student) => (
      <li key={student}>{student}</li>
    ));

    // listItems is now:
    // [<li>Alice</li>, <li>Bob</li>, <li>Charlie</li>]

  React can render an array of JSX elements directly!

map() IN A COMPONENT:

    function StudentList() {
      const students = ["Alice", "Bob", "Charlie", "Diana"];

      return (
        <ul>
          {students.map((student) => (
            <li key={student}>{student}</li>
          ))}
        </ul>
      );
    }

    Output:
      • Alice
      • Bob
      • Charlie
      • Diana

WHY THE key PROP IS REQUIRED:
  When React renders a list, it needs to track each item efficiently.
  If the list changes (item added/removed/reordered), React uses key to
  know WHICH item changed instead of re-rendering everything.

  ✅ Use a unique identifier as key (id, email, etc.):

    const students = [
      { id: 1, name: "Alice" },
      { id: 2, name: "Bob" },
      { id: 3, name: "Charlie" },
    ];

    {students.map((student) => (
      <li key={student.id}>{student.name}</li>
    ))}

  ❌ Avoid using index as key (causes bugs when list order changes):

    {students.map((student, index) => (
      <li key={index}>{student.name}</li>     ← Not recommended
    ))}

  NOTE: key is a special prop. It's ONLY for React's internal use.
  You cannot access it inside the component with props.key.

map() WITH COMPONENTS:

    const students = [
      { id: 1, name: "Alice", grade: "A", age: 20 },
      { id: 2, name: "Bob",   grade: "B", age: 22 },
      { id: 3, name: "Diana", grade: "A+", age: 19 },
    ];

    function App() {
      return (
        <div>
          {students.map((student) => (
            <StudentCard
              key={student.id}
              name={student.name}
              grade={student.grade}
              age={student.age}
            />
          ))}
        </div>
      );
    }

  One line of map() generates three StudentCard components.
  Add more students to the array? More cards appear automatically!
